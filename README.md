# マンスリー物件 周辺施設自動調査（GAS・試作版）

物件案内作成のために、物件住所を起点として以下を自動で調査し、Google Spreadsheet に保存して**掲載文とタイトルを自動生成**します。

- 周辺施設（スーパー／ドラッグストア／コンビニ／100円ショップ／大型商業施設／内科系クリニック／総合病院／郵便局／公園／チェーン系飲食店）
- 最寄り駅3駅（マイソクの記載を基に、足りない分を Google で補完。徒歩30分以上の駅はバス／車の所要時間）
- その他アクセス（最寄りバス停からの徒歩分）
- 空港からのアクセス（中部国際空港／県営名古屋空港のうち近い方。車の所要時間と有料道路の利用有無）
- タイトル（エリア／最寄り駅／設備…、60文字以内）

**使うデータは Google Geocoding API・Places API (New)・Routes API から取得したものだけです。AI による施設検索・距離推定・文章生成は一切行いません。**
徒歩分は Routes API が返す道路距離から **80m＝1分（端数切り上げ）** で算出します（不動産の表示に関する公正競争規約施行規則の基準）。Google が推定した徒歩時間は使いません。

## 構成

```
src/                 GASソース（clasp の rootDir）
  00_Config.js       シート定義・初期設定・カテゴリ・チェーン辞書の初期値
  01_Util.js         汎用関数
  02_DistanceRule.js 80m換算など表示規約に関わる計算（ここに集約）
  03_Brand.js        「他社」判定（チェーン辞書との文字列照合）
  04_Http.js         API呼び出し（リトライ・回数カウント）
  05_GoogleApis.js   Geocoding / Places (New) / Routes
  06_Facilities.js   周辺施設の検索・選定
  07_Stations.js     最寄り駅
  08_Access.js       バス停・空港
  09_Output.js       掲載文の生成（固定テンプレート）
  10_Sheets.js       シートの読み書き・初期セットアップ
  11_Main.js         メニュー・処理の流れ
  12_Title.js        タイトル生成
tests/               Node.js テスト（GAS・Google APIをモックして全処理を検証）

```

## セットアップ（マンスリー部門アカウントで実施）

1. **GCPプロジェクト**：マンスリー部門アカウントで作成し、課金アカウントを部門の管理下で紐付けます。
   次の API を有効にします：Geocoding API / Places API (New) / Routes API。
2. **APIキー**：作成したら「APIの制限」で上記3つだけを許可し、各 API に1日の上限（クォータ）を設定します。
   GAS は送信元IPで制限できないため、キーの共有範囲を最小限にしてください。
3. **スプレッドシート**：マンスリー部門の**共有ドライブ**に新規作成し、「拡張機能 > Apps Script」を開きます。
4. **コードの配置**：次のどちらかで行います。
   - clasp を使う場合：`.clasp.json.example` を `.clasp.json` にコピーしてスクリプトIDを記入し、`clasp push` を実行します。
   - 手動の場合：`src/*.js` の内容を同じ名前のファイルに貼り付け、`appsscript.json` も反映します。
5. **初期化**：スプレッドシートを再読み込みすると、メニュー「周辺調査」が表示されます。
   - 「初期セットアップ」：シートと初期設定が作成されます。
   - 「APIキー設定」：キーがスクリプトプロパティに保存されます（コードやシートには残りません）。
6. （推奨）Apps Script の「プロジェクトの設定」で、標準の GCP プロジェクト（手順1）に切り替えます。

## 使い方

1. 「物件」シートに1物件1行で入力します。
   - 必須：物件名、住所、建物名、号室
   - マイソクの駅情報：駅名・路線・徒歩分（最大3駅）
   - タイトル用の設備：チェックボックス、最大洋室帖数、Wi-Fiサービス名、その他アピール
2. 行を選択し、「① 選択した物件を調査」を実行します。
   1回目は Geocoding だけを行い、**「起点確認待ち」**で止まります。
3. 「Googleマップ」列のリンクで位置を確認します。必要なら起点緯度／経度を**建物の出入口**に修正し、「起点確認済」にチェックして再実行します。
4. 「施設結果」「駅結果」「アクセス結果」を確認します。
   - 「要確認理由」がある行：内容を確認して「確認済」にチェックします。
   - 掲載する施設：「掲載」にチェックします（クリニック・総合病院・大型商業施設は初期状態でOFFです）。
   - 駅結果：「路線」を入力します（複数路線がある場合は利用者の多い路線）。
   - アクセス結果：「運行会社」（例：名古屋市営バス）を入力します。
5. 「③ 出力を再生成」を実行すると、「出力」シートに掲載文とタイトルが作られます。
   - 再調査しても、手入力した値（路線・運行会社・掲載・確認済・備考）は引き継がれます。
   - ただし、距離や要確認理由が変わった行の「確認済」「掲載」は引き継がず、再確認の対象になります。

## 運用ルールの調整

業務ルールはすべてシート側で変更でき、コードを修正する必要はありません。

| シート | 内容 |
|---|---|
| 設定 | 30分ルール、車表示の閾値（周辺施設が徒歩20分超なら車）、空港、出発時刻、タイトル書式、保存日数など |
| カテゴリ設定 | 検索の種類・検索語、圏内上限分、最低件数、他社のみ、除外語、面積下限 |
| チェーン辞書 | 「他社」判定とチェーン系飲食店の判定に使うブランド名とキーワード |

## テスト

```bash
npm test
```

GAS の SpreadsheetApp と Google API をモックし、セットアップ → 起点確認 → 調査 → 担当者の編集 → 再調査 → 出力までを検証します。
実際の API 応答（特に日本のバス経路の可否）は、本番キーで少数の物件を試して確認してください。
