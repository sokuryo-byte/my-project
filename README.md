# マンスリー物件 周辺施設自動調査（GAS・試作版）

物件案内作成のために、**マイソクPDFから物件情報を取り込み**、物件住所を起点として以下を自動で調査し、Google Spreadsheet に保存して**掲載文とタイトルを自動生成**します。

- 周辺施設（スーパー／ドラッグストア／コンビニ／100円ショップ／大型商業施設／内科系クリニック／総合病院／郵便局／公園／チェーン系飲食店）
- 最寄り駅3駅（マイソクの記載を基に、足りない分を Google で補完。徒歩30分以上の駅はバス／車の所要時間）
- その他アクセス（最寄りバス停からの徒歩分）
- 空港からのアクセス（中部国際空港／県営名古屋空港のうち近い方。車の所要時間と有料道路の利用有無）
- タイトル（エリア／最寄り駅／設備…、60文字以内）

**使うデータは Google Geocoding API・Places API (New)・Routes API から取得したものだけです。AI による施設検索・距離推定・文章生成は一切行いません。**
徒歩分は Routes API が返す道路距離から **80m＝1分（端数切り上げ）** で算出します（不動産の表示に関する公正競争規約施行規則の基準）。Google が推定した徒歩時間は使いません。

## セットアップ（マンスリー部門アカウントで実施）

1. **GCPプロジェクト**：マンスリー部門アカウントで作成し、課金アカウントを部門の管理下で紐付けます。
   次の API を有効にします：Geocoding API / Places API (New) / Routes API。
2. **APIキー**：作成したら「APIの制限」で上記3つだけを許可し、各 API に1日の上限（クォータ）を設定します。
   GAS は送信元IPで制限できないため、キーの共有範囲を最小限にしてください。
3. **スプレッドシート**：マンスリー部門の**共有ドライブ**に新規作成し、「拡張機能 > Apps Script」を開きます。
4. **コードの配置**：次のどちらかで行います。
   - clasp を使う場合：`.clasp.json.example` を `.clasp.json` にコピーしてスクリプトIDを記入し、`clasp push` を実行します。
   - 手動の場合：`src/*.js` の内容を同じ名前のファイルに貼り付け、`appsscript.json` も反映します。
5. **初期化**：スプレッドシートを再読み込みすると、メニュー「周辺調査」が表示されます。
   - 「初期セットアップ」：シートと初期設定が作成されます。
   - 「APIキー設定」：キーがスクリプトプロパティに保存されます（コードやシートには残りません）。
6. （推奨）Apps Script の「プロジェクトの設定」で、標準の GCP プロジェクト（手順1）に切り替えます。
7. マイソク取り込み用に、共有ドライブにPDF置き場のフォルダを作り、そのURLを `設定 > mysoku_folder_id` に入れます。
   - clasp で push した場合は、拡張サービス「Drive API (v3)」が `appsscript.json` で自動的に有効になります。
   - 手動で貼り付けた場合は、エディタの「サービス」から Drive API (v3) を追加してください。

## アプリ画面（おすすめの使い方）

スプレッドシートを直接操作しなくても、1つの画面で作業を最後まで進められます。

**手順**

| 手順 | 内容 |
|---|---|
| ① 物件情報 | マイソクPDFを左上の枠にドロップ（複数可）し、読み取った内容を確認・修正する（入力は自動保存） |
| ② 位置 | 地図をクリックして、ピンを建物の出入口に合わせ、確定する |
| ③ 調査 | ボタン1つで、周辺施設・駅・バス停・空港を調べる |
| ④ 確認 | 掲載のON/OFF、要確認の「確認した」、路線・運行会社の入力 |
| ⑤ ウェルモ入力 | ウェルモの項目名どおりに内容を確認 → ウェルモで「周辺調査から入力」から選ぶだけ。保存すると入力済みが記録される |

**画面づくりの方針**
- 1つの画面に主な操作は1つだけにし、右下の固定ボタンにまとめています。
- ボタンは押しやすい大きさ（44px以上）にしています。
- 状態は色・記号・文字の3つで表示します（色の区別が難しい人でも読み取れます）。
- 文字は読みやすさに配慮したユニバーサルデザインフォント（BIZ UDPゴシック）を使っています。
- ダークモードとスマホ幅にも対応しています。

**開き方**

| 方法 | 手順 |
|---|---|
| スプレッドシートから | メニュー「周辺調査 > ★ アプリを開く」 |
| ウェブアプリとして（推奨。ブラウザのタブ全体を使えます） | Apps Script の「デプロイ > 新しいデプロイ > ウェブアプリ」で、実行ユーザー＝自分（部門アカウント）、アクセス＝組織内のユーザーにして、発行されたURLをブックマークします |

- 地図の表示には **Maps Static API** を使うので、GCPで有効にしてAPIキーの許可APIに追加してください。無効の場合は地図の代わりにメッセージが出ます。
- 画面からアップロードしたPDFは、`設定 > mysoku_folder_id` のフォルダに保存されます。未設定の場合はマイドライブ直下に保存されます。

**デモ版**
`npm run build:demo` で `dist/demo.html` ができます。架空のサンプルデータで画面を試せます。Google API とウェルモには接続しません。
`npm run test:app` を実行すると、デモ版を Chromium で操作し、一連の流れを検証します。

## 使い方

0. マイソクPDFをフォルダに置き、「⓪ マイソクフォルダから新規物件を取り込み」を実行します。
   PDFごとに物件の行が作られ、物件名・号室・所在地・交通（3駅）・駐車場・設備・構造・階数・総戸数・築年月が**空欄にだけ**入ります。
   - 既存の行に取り込む場合：「マイソクPDF」列にPDFのURLを入れ、「⓪ 選択した物件のマイソクPDFを取り込み」を実行します。
   - 読み取れなかった項目は「マイソク取込メモ」に出ます。間取図が画像の場合、洋室の帖数は読み取れません。
1. 「物件」シートで、不足している項目を入力・確認します。
   - 必須：物件名、住所、建物名、号室
   - マイソクの駅情報：駅名・路線・徒歩分（最大3駅）
   - タイトル用の設備：チェックボックス、最大洋室帖数、Wi-Fiサービス名、その他アピール
2. 行を選択し、「① 選択した物件を調査」を実行します。
   1回目は Geocoding だけを行い、**「起点確認待ち」**で止まります。
3. 「Googleマップ」列のリンクで位置を確認します。必要なら起点緯度／経度を**建物の出入口**に修正し、「起点確認済」にチェックして再実行します。
4. 「施設結果」「駅結果」「アクセス結果」を確認します。
   - 「要確認理由」がある行：内容を確認して「確認済」にチェックします。
   - 掲載する施設：「掲載」にチェックします（クリニック・総合病院・大型商業施設は初期状態でOFFです）。
   - 駅結果：「路線」を入力します（複数路線がある場合は利用者の多い路線）。
   - アクセス結果：「運行会社」（例：名古屋市営バス）を入力します。
5. 「③ 出力を再生成」を実行すると、「出力」シートに掲載文とタイトルが作られます。
   「ウェルモJSON」列には、ウェルモ「建物管理｜編集」画面の項目名に合わせた入力データがまとめて入ります。
   - 再調査しても、手入力した値（路線・運行会社・掲載・確認済・備考）は引き継がれます。
   - ただし、距離や要確認理由が変わった行の「確認済」「掲載」は引き継がず、再確認の対象になります。

## 運用ルールの調整

業務ルールはすべてシート側で変更でき、コードを修正する必要はありません。

| シート | 内容 |
|---|---|
| 設定 | 30分ルール、車表示の閾値（周辺施設が徒歩20分超なら車）、空港、出発時刻、タイトル書式、保存日数など |
| カテゴリ設定 | 検索の種類・検索語、圏内上限分、最低件数、他社のみ、除外語、面積下限 |
| チェーン辞書 | 「他社」判定とチェーン系飲食店の判定に使うブランド名とキーワード |

## テスト

```bash
npm test
```

GAS の SpreadsheetApp と Google API をモックし、セットアップ → 起点確認 → 調査 → 担当者の編集 → 再調査 → 出力までを検証します。
実際の API 応答（特に日本のバス経路の可否）は、本番キーで少数の物件を試して確認してください。

## ウェルモへの自動入力（Tampermonkey）

ウェルモ「建物管理｜編集」画面の右下に**「周辺調査から入力」**ボタンが表示されます。押すと、入力できる物件の一覧が出ます。物件を選ぶと、その物件の項目がまとめて入力されます。コピー＆貼り付けは不要です。

**はじめに（パソコンごとに1回）**
1. Chrome に拡張機能「Tampermonkey」を追加します。社内で拡張機能の許可が必要な場合は、管理者に依頼してください。
2. `npm run build:bookmarklet` で作った `dist/wellmo-autofill.user.js` を Tampermonkey に追加します。
3. ウェルモで「周辺調査から入力」→「設定」を押し、周辺調査アプリの**ウェブアプリURL**（アプリの「ウェルモ入力」画面に表示されます）を貼り付けて保存します。

**毎回の使い方**
1. 周辺調査アプリで「確認」まで進めます。
2. ウェルモの建物編集画面で「周辺調査から入力」を押し、一覧から物件の「入力」を押します。
3. 右上の結果で赤字の項目（所在地の住所検索など）だけ手で直し、「保存」を押します。
4. 保存を押すと、アプリ側にその物件の**「ウェルモ入力済」**と日時が記録されます。

**仕組みと安全性**
- データは周辺調査アプリ（GASウェブアプリ）から、ブラウザの Google ログイン状態を使って取得します。アクセスは「組織内のユーザー」に限られます。
- ウェルモのID・パスワードは使いません。保存ボタンも自動では押さず、担当者が確認して押します。
- 既存の値を空にすることはなく、建物設備は ON にするだけです。
- 予備として、Tampermonkey を使えないパソコン向けに、データを貼り付けて入力するブックマークレット（`dist/wellmo-bookmarklet.html`）もあります。

**うまく入らない項目があるとき**
ブックマークレットで「診断」と入力して実行すると、入力欄の構造（値は含みません）がコピーされます。それを開発担当に送ってください。

**検証状況**
実際のウェルモ画面ではまだ検証していません。スクリーンショットを基にした模擬ページで、Chromium を使って検証しています（`npm run test:browser`）。
