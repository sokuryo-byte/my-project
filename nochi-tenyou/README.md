# 農地転用 見積・調査支援システム（Googleスプレッドシート＋GAS）

社内メンバーが農地転用の「見積・調査依頼」を入力するWebフォームと、受け付けた案件を行政班が管理する画面です。

- **依頼画面**：物件（1筆ごと）を複数入力可。謄本をドラッグすると所在・地番・地目・地積を読み取って入力欄に入れます（要確認表示つき）。
  入力内容から概算見積を自動表示。資料はドラッグでGoogleドライブへアップロード。
  「見積調査依頼」を押すとすぐに保存され、行政班へ Google Chat で通知されます（確認画面なし）。
- **管理画面（行政班）**：案件一覧、詳細、対応状況・担当者・正式見積・メモの更新。
- 区域区分・農振などは**依頼者が選択**します。システムによる自動判定はしません。

## セットアップ手順（本番）

貼り付けるのは `dist/` の **4ファイルだけ** です（`src/` を1つにまとめたもの。`python3 tools/build_dist.py` で作成）。

1. 本番用スプレッドシートを開き、**拡張機能 > Apps Script** を開く。
2. エディタで次の4つを作り、GitHub の `dist/` の各ファイルを開いて「Copy raw file」で全文コピー → 貼り付け → 保存。
   | エディタ上の名前 | 種類 | 貼り付ける中身 |
   |---|---|---|
   | `コード.gs`（最初からあるもの） | スクリプト | `dist/Code.gs` |
   | `Index` | HTML | `dist/Index.html` |
   | `Admin` | HTML | `dist/Admin.html` |
   | `appsscript.json` | マニフェスト | `dist/appsscript.json` |
   - `appsscript.json` は **プロジェクトの設定（歯車）>「appsscript.json」マニフェスト ファイルをエディタで表示する** をONにすると出てきます。
   - これで謄本読み取り用の **Drive API（v3）** も有効になります（APIキーの取得は不要）。左の「サービス」に Drive API が出ていればOK。
3. **プロジェクトの設定 > スクリプト プロパティ** に登録：
   - `CHAT_WEBHOOK_URL`：Chat スペースの **アプリと統合 > Webhook を追加** で発行したURL
   - `ADMIN_EMAILS`：管理画面を使う行政班のメールアドレス（カンマ区切り）
4. エディタ上部で関数 `setupSpreadsheet` を選んで **実行** → 権限の確認画面で許可。
   「案件一覧」「物件明細」「マスタ」「見積設定」シートと、ドライブに「農地転用_案件資料」フォルダが作成されます。
5. **「農地転用_案件資料」フォルダを行政班のメンバーに共有**する（資料を閲覧するため）。
6. スプレッドシートを再読み込み → メニュー **農地転用システム > Google Chat 通知テスト** で通知を確認。
7. **デプロイ > 新しいデプロイ > 種類：ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**（組織名）内の全員** ← 社内Googleアカウントに限定
8. 発行されたURL（`…/exec`）を社内ポータルへ。管理画面は同じURLの末尾に `?page=admin` を付けたものです。
   - **Google サイトのポータルに埋め込む場合**：ページ編集 > 挿入 > 埋め込む > URL にこのURLを入力（依頼画面は埋め込み可能に設定済み）。
   - リンクで置く場合は、URLをそのままボタンやリンクに設定。

> コード修正後は `python3 tools/build_dist.py` で `dist/` を作り直して貼り直し、**デプロイを管理 > 編集 > バージョン：新バージョン** で更新（URLは変わりません）。
> 「見積設定」「マスタ」シートの変更は再デプロイ不要で即反映されます。

## 誰が使えるか

- 「アクセスできるユーザー：組織内の全員」にすると、**会社の Google Workspace アカウントでログインした人だけ**が使えます。社外の人・個人の Gmail では開けません。
- 場所は問いません。会社のアカウントでログインしていれば、自宅や外出先、スマートフォンからも使えます（社内ネットワーク限定ではありません）。
- 管理画面はさらに `ADMIN_EMAILS` に登録した人だけ。

## 見積パラメータの設定（「見積設定」シート）

| キー（変更しない） | 項目名（見積に表示） | 金額（円・税込） | 適用条件 |
|---|---|---|---|
| BASE_SHIGAIKA | 基本報酬（市街化区域：届出） | 50,000 | 市街化区域、または区域「分からない」 |
| BASE_CHOSEI | 基本報酬（市街化調整区域：許可） | 120,000 | 市街化調整区域 |
| BASE_HISENBIKI | 基本報酬（非線引き区域：許可） | 120,000 | 非線引き区域 |
| ADD_NOSHIN | 農振除外手続き 加算 | 150,000 | 農振農用地「はい」 |
| ADD_LAND_IMPROVEMENT | 土地改良区 地区除外手続き 加算 | 50,000 | 土地改良区「はい」 |
| ADD_ALREADY_CONVERTED | 現況是正・事後手続き 加算 | 50,000 | 転用済み「はい」、または現況が駐車場・宅地・資材置場の物件がある |
| ADD_PER_EXTRA_LOT | 物件（筆）追加 加算（1筆あたり） | 10,000 | 同じ申請に含まれる2筆目以降1筆ごと |

**複数物件の計算方法**
- 基本報酬は**区域区分ごとに1回**（同じ区域の物件は1つの申請にまとめる想定）。区域が違う物件があれば申請を分ける想定で、それぞれの基本報酬を計上。
- 物件数が申請数を超える分は「物件（筆）追加 加算」× 筆数。
- 農振除外・地区除外・事後手続きは、該当する物件が1つでもあれば1回加算。

- **金額と項目名はシート上で自由に変更できます**（空欄・数値以外の場合は `Config.gs` の初期値を使用）。
- 区域が「分からない」場合は、原則どおり**届出（市街化区域）前提**で計算します（`FALLBACK_ZONE_FOR_UNKNOWN`）。
- 農振・土地改良区が「分からない」場合は加算せず、「該当すれば +○円」と注意書きを表示します。
- 条件そのもの（どの入力で加算するか）を変える場合は `Estimate.gs` を修正します。

## 入力ルール

- 物件所在地は「都道府県（初期値：愛知県）＋市区町村から始まる所在」の2項目。市区町村を別欄では入力しません。
  所在の先頭がマスタの市区町村名と一致した場合だけ、市区町村列に自動で記録し、参照用リンクを表示します（前方一致のみ・推測なし）。

- 必須：依頼者名、物件ごとの地番・区域区分（「分からない」可）
- **現況が農地（耕作中・休耕・荒地）の物件がある場合は「今後の転用計画」も必須**（`FARMLAND_LAND_USES`）
- 物件は1件の依頼で最大30件（`MAX_LOTS`）。「最後の物件の区域などを引き継いで追加」で、所在・区域・農振・現況などを引き継いだカードを追加できます。

## 謄本の読み取り

1. 「謄本から読み取る」枠（または資料欄の「謄本」枠）に謄本のPDF・画像をドラッグ。**何通でもまとめて入れられます**（同時に処理するのは3通ずつで、残りは「待機中」で順番に処理）。
2. ドライブにアップロード後、**Googleドライブの文字認識（OCR）**で文字にし、決まったパターンだけを取り出します（AIによる推測はしません）。
   - 所在：「所在」の行（最後に出てくる行＝最新）
   - 地番・地目・地積：「123番1 畑 496」のような行の最後の行（変更履歴がある場合は最新の行）
   - 1つのファイルに複数の謄本があれば「表題部」ごとに複数の物件として読み取ります。
3. 読み取った値は**空欄にだけ**入れ、黄色で表示し、物件に「謄本から読取・要確認」と出します。人が入力済みの欄は上書きしません。
4. 読み取れなかった場合は「手入力してください」と表示されるだけで、送信には影響しません。

注意：抹消事項の下線は文字認識では判別できないため、最終行を最新とみなしています。区域・農振・現況は謄本に無いため手で選びます。**必ず謄本と見比べて確認してください。**
- 送信ボタンを押すと確認画面なしで即送信。二重送信は防止しています。

## 資料のアップロード（Googleドライブ）

1. 資料種別（謄本・公図・住宅地図・課税明細・その他）ごとの枠にファイルをドラッグ → すぐに `_受付中（未送信）` フォルダへ保存。
2. 送信すると案件フォルダ（例：`0042_豊田市_123番1`）が作られ、ファイルが `[公図] ファイル名.pdf` の形で移動します。
3. 送信されずに残ったファイルは、メニュー **未送信の一時ファイルを削除（7日以上前）** で掃除できます。

- 形式：PDF・画像（`ALLOWED_MIME_TYPES`）、1ファイル10MBまで（`MAX_UPLOAD_MB`）
- 画面からは一時フォルダ内のファイルしか移動・削除できないようにしています（他のファイルは操作不可）。

## 管理画面（行政班）

- URL：`…/exec?page=admin`（`ADMIN_EMAILS` に登録された人だけ表示）
- Chat 通知の「管理画面で案件を開く」リンクから、その案件を直接開けます。
- 一覧：対応状況で絞り込み、検索、「見積調査依頼のみ」表示。
- 詳細：依頼内容・見積内訳・資料フォルダへのリンク。
- 更新できる項目：**対応状況**（新規／調査中／正式見積提示済／受任／完了／失注・取下げ）、**担当者**、**正式見積金額**、**対応メモ**。
  依頼内容そのものは管理画面から書き換えません（必要ならシートを直接修正）。

## スプレッドシート構成

### 案件一覧

| 列 | 見出し | 内容 |
|---|---|---|
| A | ID | 自動採番 |
| B | 受付日時 | |
| C〜G | 依頼者名／物件所在地／地番／地目／面積 | |
| H | 市街化区域／調整区域 | 市街化区域／市街化調整区域／非線引き区域／分からない |
| I | 農振農用地 | TRUE／FALSE／不明 |
| J | 現況利用 | 例：`駐車場（一部物置あり）` |
| K | 既に転用済み | TRUE／FALSE |
| L | 今後の転用計画 | |
| M | 土地改良区の有無 | はい／いいえ／分からない |
| N | 添付資料の有無 | カンマ区切り 例：`謄本,公図,その他（測量図）` |
| O | 概算見積金額 | |
| P | 見積調査依頼フラグ | TRUE＝依頼（通知あり）／FALSE＝保存のみ |
| Q〜V | 補助列 | 都道府県、市区町村、水利組合・農事組合、見積内訳、入力者、Chat通知結果 |
| W〜AC | 資料・対応管理 | 資料フォルダURL、アップロード件数、対応状況、担当者、正式見積金額、対応メモ、最終更新 |

### 物件明細

1物件（1筆）＝1行。`案件ID` で案件一覧とつながります。列：案件ID、物件No、所在、地番、地目、面積、区域区分、農振農用地、現況利用、既に転用済み、土地改良区、市区町村（所在から自動）、謄本から読取。
案件一覧の地番・地目・面積・区域などの列は、全物件の**まとめ**（地番は「、」区切り、面積は合計、農振は「いずれかがはい」ならTRUE）です。

列を増やすときは `Config.gs` の `CASE_COLUMNS`（物件は `LOT_COLUMNS`）の**末尾**に追加し、`setupSpreadsheet` を再実行してください。
（既存のシートで再実行すると、足りない見出しだけが右側に追記されます。）

### マスタ

`都道府県 | 市区町村 | 都市計画情報URL | 農振図URL | 備考`

- 行を追加するだけで反映。所在が「豊田市…」のように市区町村名で始まると、その行のURLを参照用リンクとして表示します（自動判定ではありません）。
- マスタに無い市区町村でも入力・送信はできます（市区町村列が空欄になるだけです）。

## 壊れにくさのための工夫

- **保存 → 資料移動 → 通知** の順で処理。途中で失敗しても案件は残り、失敗内容がシートと画面に出ます。
- ID採番〜書き込み、管理画面の更新は `LockService` で排他制御。
- 入力値・管理画面の更新値はサーバー側で再チェック（選択肢外の値の除外、文字数制限、管理者チェック）。
- `=` `+` `-` `@` で始まる入力は数式として実行されないよう、先頭に `'` を付けて保存。

## 動作確認（開発者向け）

`test/` に、実際の画面（Index.html / Admin.html）と .gs のコードを、Google のサービスを模擬した状態でブラウザ上で動かす仕組みがあります。
コードを直したら、Google に反映する前にここで確認できます（Node.js と Playwright が必要）。

```
cd nochi-tenyou/test
python3 build.py        # test/out/index.html, admin.html を作成（ブラウザで直接開いても操作できます）
node e2e.js             # 謄本読取 → 複数物件 → 見積 → 送信 → 管理画面 までを自動で確認
```
