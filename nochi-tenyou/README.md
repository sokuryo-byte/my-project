# 農地転用 見積・調査支援システム（Googleスプレッドシート＋GAS）

社内メンバーが農地転用の「見積・調査依頼」を入力するWebフォームと、受け付けた案件を行政班が管理する画面です。

- **依頼画面**：物件（1筆ごと）を複数入力可。謄本をドラッグすると所在・地番・地目・地積を読み取って入力欄に入れます（要確認表示つき）。
  入力内容から概算見積を自動表示。資料はドラッグでGoogleドライブへアップロード。
  「見積調査依頼」を押すとすぐに保存され、行政班へ Google Chat で通知されます（確認画面なし）。
- **管理画面（行政班）**：案件一覧、詳細、対応状況・担当者・正式見積・メモの更新。
- 区域区分・農振などは**依頼者が選択**します。システムによる自動判定はしません。
  （ただし区域区分で市街化区域を選ぶと、農振農用地は「いいえ」が初期選択されます。変更可）

## セットアップ手順（本番）

貼り付けるのは `dist/` の **4ファイルだけ** です（`src/` を1つにまとめたもの。`python3 tools/build_dist.py` で作成）。

1. 本番用スプレッドシートを開き、**拡張機能 > Apps Script** を開く。
2. エディタで次の4つを作り、GitHub の `dist/` の各ファイルを開いて「Copy raw file」で全文コピー → 貼り付け → 保存。
   | エディタ上の名前 | 種類 | 貼り付ける中身 |
   |---|---|---|
   | `コード.gs`（最初からあるもの） | スクリプト | `dist/Code.gs` |
   | `Index` | HTML | `dist/Index.html` |
   | `Admin` | HTML | `dist/Admin.html` |
   | `appsscript.json` | マニフェスト | `dist/appsscript.json` |
   - `appsscript.json` は **プロジェクトの設定（歯車）>「appsscript.json」マニフェスト ファイルをエディタで表示する** をONにすると出てきます。
   - これで謄本読み取り用の **Drive API（v3）** も有効になります（APIキーの取得は不要）。左の「サービス」に Drive API が出ていればOK。
3. **プロジェクトの設定 > スクリプト プロパティ** に登録：
   - `CHAT_WEBHOOK_URL`：Chat スペースの **アプリと統合 > Webhook を追加** で発行したURL
   - `ADMIN_EMAILS`：管理画面を使う行政班のメールアドレス（カンマ区切り）
4. エディタ上部で関数 `setupSpreadsheet` を選んで **実行** → 権限の確認画面で許可。
   「案件一覧」「物件明細」「マスタ」「見積設定」シートと、ドライブに「農地転用_案件資料」フォルダが作成されます。
5. **「農地転用_案件資料」フォルダを行政班のメンバーに共有**する（資料を閲覧するため）。
6. スプレッドシートを再読み込み → メニュー **農地転用システム > Google Chat 通知テスト** で通知を確認。
7. **デプロイ > 新しいデプロイ > 種類：ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**（組織名）内の全員** ← 社内Googleアカウントに限定
8. 発行されたURL（`…/exec`）を社内ポータルへ。管理画面は同じURLの末尾に `?page=admin` を付けたものです。
   - **Google サイトのポータルに埋め込む場合**：ページ編集 > 挿入 > 埋め込む > URL にこのURLを入力（依頼画面は埋め込み可能に設定済み）。
   - リンクで置く場合は、URLをそのままボタンやリンクに設定。

> コード修正後は `python3 tools/build_dist.py` で `dist/` を作り直して貼り直し、**デプロイを管理 > 編集 > バージョン：新バージョン** で更新（URLは変わりません）。
> 「見積設定」「マスタ」シートの変更は再デプロイ不要で即反映されます。

**信託手続きに付随する依頼**（依頼者欄のチェック）は、農地転用の基本報酬を1.5倍にします（`TRUST_MULTIPLIER`）。
概算見積は **報酬** と **実費** に分けて表示し、合計は両方の和です。実費は調査実費、地区除外決済金、土地改良区の手数料等、排水承諾（用水）の手数料等。
決済金は「総額／㎡あたり／haあたり」で入力し、単価の場合は**同じ土地改良区（名称）で受益地に該当する物件の面積合計**で計算します（改良区・用水の手数料は改良区・用水ごとに1回）。
概算見積は依頼画面の中で即時に計算します（`tools/build_dist.py` が Config.gs・Estimate.gs・WebApp.gs を画面にも同梱。料金は画面を開いたときに「見積設定」シートから受け取る）。送信時はサーバーで同じコードにより再計算して保存します。

金額は「2026基本料金改定案」行政書士シートの報酬に合わせています。料金表を改定したときは `Config.gs` の `DEFAULT_FEES` を直し、
`FEE_TABLE_VERSION` を変えてデプロイすると、次に画面が開かれたときに「見積設定」シートへ1回だけ反映されます。

**複数物件の計算方法**
- 基本報酬は**区域区分ごとに1回**（同じ区域の物件は1つの申請にまとめる想定）。区域が違う物件があれば申請を分ける想定で、それぞれの基本報酬を計上。
- 物件数が申請数を超える分は「物件（筆）追加 加算」× 筆数。
- 農振除外・地区除外・事後手続きは、該当する物件が1つでもあれば1回加算。
- 区域「分からない」の物件が転用済みに該当する場合は加算せず、「許可の区域なら +○円」と注意書きを表示します。

- **金額と項目名はシート上で自由に変更できます**（空欄・数値以外の場合は `Config.gs` の初期値を使用）。
- 区域が「分からない」場合は、原則どおり**届出（市街化区域）前提**で計算します（`FALLBACK_ZONE_FOR_UNKNOWN`）。
- 農振が「分からない」場合は加算せず、「該当すれば +○円」と注意書きを表示します。
- 土地改良区・地元関係者の同意が「分からない」場合は**加算**し、「該当しない場合は減額」と注意書きを表示します。
- 条件そのもの（どの入力で加算するか）を変える場合は `Estimate.gs` を修正します。

## 入力ルール

- 物件の場所は「都道府県（初期値：愛知県）」「**市区町村**」「**所在・地番**（町名・字〜地番、例：`○○町字△△ 123番1`）」の3項目。
  - 都道府県は**物件ごと**（物件カードの先頭）。市区町村の入力候補は三県すべての市町村で、入力した市町村名や謄本の所在がほかの1県だけに当てはまる場合は、その物件の都道府県を自動で切り替えます（例：岐阜市→岐阜県、謄本の桑名市→三重県）。
  - 市区町村欄は愛知・岐阜・三重の全市町村（`Config.gs` の `MUNICIPALITIES`）＋マスタの市区町村が入力候補に出ます（候補外も入力可）。
  - 所在・地番欄の**末尾の数字部分**（`123番1`／`123番地1`／`123-1`／`123`）を地番として切り出し、シートには 所在＝市区町村＋町名・字、地番＝切り出した地番 に分けて保存します（`LOT_NUMBER_TAIL_RE`）。
  - 市区町村欄がマスタの市区町村名と一致すると、都市計画情報・農振図の参照用リンクを表示します。

- 必須：依頼者名、物件ごとの市区町村・所在地番（末尾に地番があること）・区域区分（「分からない」可）
- **現況が農地（耕作中・休耕・荒地）の物件がある場合は「今後の転用計画」も必須**（`FARMLAND_LAND_USES`）
- 物件は1件の依頼で最大30件（`MAX_LOTS`）。「最後の物件の区域などを引き継いで追加」で、市区町村・町名字（地番は除く）・区域・農振・現況などを引き継いだカードを追加できます。

## 土地改良区の電話確認

物件ごとの「土地改良区にかかっているか」の欄に、**その市区町村の農業委員会の電話番号とトーク例**を表示します。
依頼者が電話で確認し、結果を入力する流れです。

1. **① 農業委員会へ確認**：市区町村を入力すると、農業委員会の窓口名と電話番号（スマートフォンではタップで発信）が出ます。
   トーク例には入力した所在・地番が入ります。あわせて**地元の農業委員・農地利用最適化推進委員の押印が必要か**も確認し、
   「必要」の場合は委員の**氏名・住所・電話番号**を入力します（ごくまれに必要な市町があるため。複数人可）。
2. 「はい（かかっている）」を選ぶと **② 土地改良区へ確認** が開きます。農業委員会から聞いた土地改良区名・電話番号を入力し、
   トーク例に沿って **受益地に該当するか**・**地区除外の決済金が必要か（金額）**・**地元関係者（自治会長・水利組合・地元の委員や理事など）の同意（押印）が必要か** を確認して入力します。
   同意が必要な方は**氏名・住所・電話番号**を入力します（複数人可、最大5人）。

3. **転用目的が「分家住宅」** のときは **排水先の確認** が開きます。隣接の水路へ排水できるか、ない場合は側溝の流末が農業用水か、
   農業用水なら排水承諾が必要か（用水の名称・電話・手数料）、地元承諾が必要か（氏名・住所・電話）を確認して入力します。
4. **青地（農振「はい」または「分からない」、市街化区域以外）** のときは、①の**最初に農振除外の見込み**を聞きます。
   位置関係（中央部か・歯抜けか・市街化区域に接しているか）は農振図で分かるので聞かず、ほ場整備などの**土地改良事業の区域か**、
   区域内なら**完了から8年経過したか**、**近隣の除外実績**、**除外の受付時期**を聞いて記録します（8年未経過は除外の要件を満たさないため、そこで打ち切り）。
5. 区域区分が**許可の区域（市街化調整・非線引き・都市計画区域外）** のときは、続けて **転用の見込み** を聞きます（青地でなければ①の最初）。
   前置きは「申請の準備を進める前に、何点か確認させてください」だけにし、農地区分・優良農地の一団か・事前相談で指摘されやすい点という事実を聞きます。
   「結論は審査次第」と言われたときだけ「もちろん承知しています。〜だけでも教えていただけると、事前相談の準備がしやすくなります」と切り返し、
   それでも回答がなければ事前相談の窓口・担当者を聞きます。
   ※ 転用の見込みで聞くのは「青地か白地か」と「農地区分」だけ（優良農地の一団や周辺状況は現地・図面で分かるため聞かない）。
6. 除外の見込みで「ほ場整備の区域内」と分かった場合は、（ア）で土地改良区にかかっているかを聞き直さず（自動で「はい」）、名称と電話番号の確認だけにします。
   「区域外」なら「用排水などで土地改良区の区域にかかっているか」と聞きます。
7. **受付期間**は専用欄で記録します：農地転用は「毎月［ ］日～［ ］日」または「締切日［日付］」、農振除外は「受付期間（次回）［日付］～［日付］」。
8. **転用目的**（分家住宅・駐車場・資材置場・その他）は、区域区分で**市街化調整区域**を選んだ物件だけ、区域区分のすぐ下に表示します。
   分家住宅なら分家建築許可の加算と排水先の確認が加わります。案件一覧の「転用目的」列には各物件の目的をまとめて記録します。

- **見込みが「難しい」**（転用の見込み、または青地の除外の見込み）を選ぶと、その先（土地改良区・地元委員・排水）のトークと確認欄は表示せず、「以降の確認は不要」と表示します。
- ② 土地改良区では、**受益地に該当する場合だけ**「地区除外の手続き（必要／不要）」と「決済金」を聞き、**決済金が必要な場合だけ**金額欄を出します。
  決済金がなくても手続きが必要な改良区があるため、手続きの要否は別に記録し、手続きが「不要」なら地区除外の加算をしません。
  決済金は金額（円）のみ。決済金とは別の**手数料など**は金額と内容を別欄に記録します（いずれも実費のため見積には含めず注記）。
- 区域区分の目安（課税明細書の都市計画税）は、**都市計画税を課していない市町村**（`Config.gs` の `NO_CITY_PLANNING_TAX`。総務省 令和6年度決算・
  岐阜県 令和6年度税率表・三重県 令和7年度税率一覧・各市例規集で確認）では使えないため、市区町村を入れるとその旨を※で表示します。
  あま市は令和9年度から課税予定、蟹江町は令和7年度から課税のため対象外。**年度が変わったら見直してください。**
- **既に転用済み「はい」** の物件は、①の最初に **過去の転用の履歴** を確認します（市街化区域は転用届出の受理、調整区域などは転用許可）。
  履歴「あり」なら受理・許可年月日、番号、内容を記録し、見積の最後の注記に「新たな手続きが不要な場合があります」と表示します。
- **登記地目が農地以外**（田・畑以外）を選ぶと、手入力でも謄本の読み取りでも「農地転用の手続きは原則不要です」の確認ウインドウを出します。
  「地目を修正する」で閉じて修正、「農地以外で間違いない」で物件が複数ならその物件を外し、1件だけなら依頼の終了を促す画面にします（謄本で複数入った場合は順に確認）。
- 現況利用と「既に転用済み」が食い違う場合（現況が駐車場・宅地・資材置場なのに「いいえ」、現況が農地なのに「はい」）は、画面と見積の注記に注意を表示します。

- 転用目的が分家住宅（市街化調整区域の物件）であれば
  **分家建築許可申請（4001、290,000円）**、排水承諾が「不要」と確認できるまでは **排水承諾手続（4203、35,000円）** を加算します。用水の手数料は実費として注記に表示します。
- 電話番号は愛知・岐阜・三重の全市町村について、各市町村の公式サイトで確認したものを `Config.gs` の `NOGYO_IINKAI` に収録（確認したページのURL付き）。
  番号が変わった場合は「マスタ」シートの「農業委員会 電話番号」列に入力すると、そちらが優先されます。
- 見積：地区除外の加算は「はい」または「分からない」で加算。土地改良区に**受益地に該当しない**と確認できた物件は加算しません。
  決済金は実費のため見積に含めず、「必要」の場合は注記に金額を表示します。
- 確認結果（土地改良区名・電話・受益地該当・決済金）は物件明細シートと Chat 通知、管理画面の物件明細に出ます。

## 謄本の読み取り

1. 「謄本から読み取る」枠（または資料欄の「謄本」枠）に謄本のPDF・画像をドラッグ。**何通でもまとめて入れられます**（同時に処理するのは3通ずつで、残りは「待機中」で順番に処理）。
2. ドライブにアップロード後、**Googleドライブの文字認識（OCR）**で文字にし、決まったパターンだけを取り出します（AIによる推測はしません）。
   - 所在：「所在」の行（最後に出てくる行＝最新）。先頭の市区町村（郡名付きも可）を市区町村欄へ、残りを所在・地番欄へ入れます
   - 地番・地目・地積：「123番1 畑 496」のような行の最後の行（変更履歴がある場合は最新の行）
   - 1つのファイルに複数の謄本があれば「表題部」ごとに複数の物件として読み取ります。
3. 読み取った値は**空欄にだけ**入れ、黄色で表示し、物件に「謄本から読取・要確認」と出します。人が入力済みの欄は上書きしません。
4. 読み取れなかった場合は「手入力してください」と表示されるだけで、送信には影響しません。

注意：抹消事項の下線は文字認識では判別できないため、最終行を最新とみなしています。区域・農振・現況は謄本に無いため手で選びます。**必ず謄本と見比べて確認してください。**
- 送信ボタンを押すと確認画面なしで即送信。二重送信は防止しています。

## 資料のアップロード（Googleドライブ）

1. 資料種別（謄本・公図・住宅地図・課税明細・その他）ごとの枠にファイルをドラッグ → すぐに `_受付中（未送信）` フォルダへ保存。
2. 送信すると案件フォルダ（例：`0042_豊田市_123番1`）が作られ、ファイルが `[公図] ファイル名.pdf` の形で移動します。
3. 送信されずに残ったファイルは、メニュー **未送信の一時ファイルを削除（7日以上前）** で掃除できます。

- 形式：PDF・画像（`ALLOWED_MIME_TYPES`）、1ファイル10MBまで（`MAX_UPLOAD_MB`）
- 画面からは一時フォルダ内のファイルしか移動・削除できないようにしています（他のファイルは操作不可）。

## 管理画面（行政班）

- URL：`…/exec?page=admin`（`ADMIN_EMAILS` に登録された人だけ表示）
- Chat 通知の「管理画面で案件を開く」リンクから、その案件を直接開けます。
- 一覧：対応状況で絞り込み、検索、「見積調査依頼のみ」表示。
- 詳細：依頼内容・見積内訳・資料フォルダへのリンク。
- 更新できる項目：**対応状況**（新規／調査中／正式見積提示済／受任／完了／失注・取下げ）、**担当者**、**正式見積金額**、**対応メモ**。
  依頼内容そのものは管理画面から書き換えません（必要ならシートを直接修正）。

### 設定タブ

管理画面上部の「設定」タブで、次の項目を変更できます（管理者のみ）。
- **概算見積の金額・項目名**：「見積設定」シートに保存され、依頼画面に即時反映（適用条件の変更は `Estimate.gs` の改修が必要）
- **管理者**：スクリプトプロパティ `ADMIN_EMAILS` に保存。自分自身は外せません（締め出し防止）
- **Google Chat 通知**：スクリプトプロパティ `CHAT_WEBHOOK_URL` に保存。「テスト送信」で到達確認
- スプレッドシート（マスタ編集用）・資料フォルダへのリンク

### 物件明細

1物件（1筆）＝1行。`案件ID` で案件一覧とつながります。列：案件ID、物件No、所在、地番、地目、面積、区域区分、農振農用地、現況利用、既に転用済み、土地改良区、市区町村、謄本から読取。
案件一覧の地番・地目・面積・区域などの列は、全物件の**まとめ**（地番は「、」区切り、面積は合計、農振は「いずれかがはい」ならTRUE）です。

列を増やすときは `Config.gs` の `CASE_COLUMNS`（物件は `LOT_COLUMNS`）の**末尾**に追加し、`setupSpreadsheet` を再実行してください。
（既存のシートで再実行すると、足りない見出しだけが右側に追記されます。）

### マスタ

`都道府県 | 市区町村 | 都市計画情報URL | 農振図URL | 備考`

- 行を追加するだけで反映。物件の市区町村欄がこの名前と一致すると、その行のURLを参照用リンクとして表示します（自動判定ではありません）。
- マスタに無い市区町村でも入力・送信はできます（市区町村列が空欄になるだけです）。

## 壊れにくさのための工夫

- **保存 → 資料移動 → 通知** の順で処理。途中で失敗しても案件は残り、失敗内容がシートと画面に出ます。
- ID採番〜書き込み、管理画面の更新は `LockService` で排他制御。
- 入力値・管理画面の更新値はサーバー側で再チェック（選択肢外の値の除外、文字数制限、管理者チェック）。
- `=` `+` `-` `@` で始まる入力は数式として実行されないよう、先頭に `'` を付けて保存。

## エラーログ

謄本の読み取りや資料のアップロードに失敗すると、スプレッドシートの「エラーログ」シート（初回のエラー時に自動作成）に
日時・ユーザー・処理・エラー内容を記録します。原因調査に使ってください。

## 動作確認（開発者向け）

`test/` に、実際の画面（Index.html / Admin.html）と .gs のコードを、Google のサービスを模擬した状態でブラウザ上で動かす仕組みがあります。
コードを直したら、Google に反映する前にここで確認できます（Node.js と Playwright が必要）。

```
cd nochi-tenyou/test
python3 build.py        # test/out/index.html, admin.html を作成（ブラウザで直接開いても操作できます）
node e2e.js             # 謄本読取 → 複数物件 → 見積 → 送信 → 管理画面 までを自動で確認
```
