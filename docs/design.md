# 設計メモ（試作版）

## 1. 処理の流れ

```
物件シート（住所・マイソク駅・設備）
  │ Geocoding API ………… 起点座標・エリア（address_components）
  ▼
起点確認待ち ── 担当者が建物出入口に座標を合わせ「起点確認済」にチェック
  ▼
Places API (New) ………… カテゴリ別の施設候補・駅・バス停（営業中のみ）
Routes API (Matrix/WALK) … 道路距離 → 徒歩分 = ceil(距離 / 80)
Routes API (DRIVE) ……… 徒歩20分超の施設・徒歩30分以上の駅・空港（有料道路の判定を含む）
Routes API (TRANSIT/BUS)… 徒歩30分以上の駅（バス経路が返る地域のみ）
  ▼
施設結果・駅結果・アクセス結果（要確認理由つき）── 担当者が確認・掲載・路線・運行会社を入力
  ▼
出力（周辺施設文・駅・その他アクセス・空港・タイトル）……… 固定テンプレートのみ
```

## 2. 選定ルール（決定的なルールのみ。AI判断なし）

| カテゴリ | 規則 |
|---|---|
| スーパー／ドラッグストア／コンビニ | 道路距離順。徒歩10分以内の**他社**（同一ブランドは最寄り1店）をすべて採用。圏内に1件もなければ圏外の最寄り1件 |
| 100円ショップ | 徒歩10分以内にあれば（他社のみ） |
| 大型商業施設 | 徒歩15分以内にあれば。大型かどうかは担当者が確認（初期は掲載OFF） |
| 内科系クリニック | 「内科」で Text Search を行い、最寄り1件。歯科・眼科などは除外。診療科は担当者が確認 |
| 総合病院 | hospital 種別で名称に「病院」を含むもの、徒歩15分以内。総合病院かどうかは担当者が確認 |
| 郵便局 | 最寄り1件（ATM・ゆうちょ銀行は除外） |
| 公園 | 徒歩10分以内で、viewport（外接矩形）の概算面積が下限（初期値 10,000㎡）以上 |
| チェーン系飲食店 | チェーン辞書に一致する店のみ。徒歩10分以内の他社をすべて。最低3件（不足分は圏外から近い順） |

- 採用した施設が徒歩20分を超える場合は、車の所要時間を取得して「〇〇まで車で約n分」と表示します。閾値は設定で変更できます。
- 「他社」の判定はチェーン辞書との文字列照合で行います。辞書にない店は、名称の最初の空白までをブランドとして扱います。
- Nearby Search は1回の検索で最大20件しか返りません。上限に達した場合は「漏れの可能性」を要確認に出します。

## 3. 駅

1. マイソクの駅（最大3件）を基にし、足りない分は Google で近い順に補います。同じ駅名の重複は1件にまとめます。
2. Google 由来の徒歩分 = 道路距離 ÷ 80（切り上げ）。マイソクより短ければ Google の値を採用します。
3. 採用した徒歩分が30分以上の場合は、徒歩分を空欄にして「バスでn分」（徒歩を含む）を出します。バス経路が取得できない場合は「車でn分」にします。
4. 路線の選択（利用者の多い路線）は API から取得できないため、担当者が入力します。
5. Places の駅座標は駅の代表点で、**出入口ではありません**。Google の値を採用した行には常に要確認を付けます。

## 4. タイトル

- エリア：Geocoding の address_components から作ります。名古屋市は「〇〇区」、それ以外は「県＋市」（設定で「市のみ」に変更可）。物件シートで上書きできます。
- 最寄り駅：駅結果のうち採用徒歩分が最短の駅。徒歩10分以内なら「〇〇駅徒歩n分」、超える場合は「〇〇駅」のみ。
- 設備：物件シートの入力値を使います（API では取得できないため）。USEN AIR は無料Wi-Fiとして扱いません。駐車場がある物件には自転車駐輪可能を書きません。
- その他アピール：手入力を優先します。空欄の場合は、担当者が掲載チェックした大型商業施設（徒歩圏）を使います。
- 60文字を超える場合は、後ろの要素から削ります。削った要素は「タイトル注記」に記録します。

## 4.5 マイソク取り込み

- PDF は Google ドライブの変換機能（PDF→Googleドキュメント、日本語OCR）でテキストにします。一時ドキュメントは変換後に削除します。
- 「物件名」「号室名」「所在地」「交通」「駐車場」「設備」「建築構造」「築年」などの見出しを正規表現で読み取ります。AI による推測は行いません。
- 物件シートの**空欄だけ**を埋め、手入力は上書きしません。チェックボックスは ON にするだけで、OFF にはしません。
- 交通欄の「路線「駅」徒歩n分」は、マイソク駅1〜3に入ります（バス停の行は除外）。
- 読み取れない項目（画像の間取図にある帖数など）は「マイソク取込メモ」に出します。
- 動作確認は RealNetPro 形式（添付サンプル）のテキストで行いました。実際の PDF を変換した結果は、本番環境で確認する必要があります。

## 4.6 ウェルモ入力データ

「出力」シートの「ウェルモJSON」列に、画面の項目名をキーにしたデータを作ります。

主な項目：マンスリー表示名、建物名、物件種別、所在地（郵便番号・住所）、緯度・経度（起点を確認済みの場合のみ）、周辺環境、最寄り駅×3（路線・駅・徒歩・その他）、その他アクセス、空港からのアクセス、建物設備、建物構造、建物階数、築年月、総戸数。

- 値が空の項目は含めません（画面の既存値を消さないため）。
- ふりがなは API やマイソクから得られないため、担当者の入力が前提です。
- 最寄り駅の「路線」は、ウェルモの選択肢の表記（例：「名古屋市鶴舞線」）と合わない場合があります。自動入力ツール側に対応表を用意します。

## 5. 法令・規約上の注意（法的助言ではありません。運用開始前に協議会・顧問弁護士に確認してください）

- **徒歩分**：道路距離80m＝1分、端数は切り上げ（公正競争規約施行規則）。計算は `02_DistanceRule.js` の1か所にまとめています。
- **起点・終点**：規約上は、物件の出入口から施設（駅）の出入口まで。座標のずれは過小表示につながるため、起点の確認を必須にし、道路距離が直線距離より短い場合などに要確認を付けます。
- **車の所要時間**：施行規則では道路距離の明示が求められています。掲載例に合わせて初期値は距離を表示しない設定にしています。`設定 > show_drive_distance` を TRUE にすると「（約x.xkm）」を併記します。**運用方針を決めて設定してください**。
- **バスの所要時間**：Google の時刻表に基づく値で、検索時刻によって変わります。乗車時間・停留所名は「代替詳細」に残します。
- **現に利用できる施設**：閉業・休業中の施設は除外しますが、Google の情報更新が遅れることがあるため、担当者の確認を前提にしています。
- **Google Maps Platform の利用規約**：place_id 以外のデータには保存制限があります。保存日数を設定し、「保存期限切れデータの整理」で削除します。印刷物などでの利用条件と出典表記は、最新の規約を確認してください。

## 6. 距離精度の検証（運用開始前）

1. 都心・郊外の物件10件程度 × カテゴリ5種程度で約50経路を選びます。駅の複数出入口、大きな公園・病院、踏切、川を渡る経路を含めます。
2. 実際に歩いて測るか、国土地理院地図の距離計測を手作業で行い、正解値とします。
3. 指標：距離の平均絶対誤差、±10%以内に収まる割合、**徒歩分の過小表示の件数（目標0件）**。
4. 過小表示の傾向が見つかったら、出入口座標の補正を必須にするなど、安全側の運用ルールを追加します。
5. 同じ経路を定期的に再計算し、Google 側のデータ変更による差分を監視します。
